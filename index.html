查看腳位表
先確認型號

本教學適用 ESP32-WROOM-32／ESP32 DevKit V1（需有 GPIO 16、17），搭配單片 64×32、1/16 掃描、標準移位暫存器型 HUB75 面板。ESP32-C3／C6、WROVER／PSRAM 占用 16、17 的開發板、S3 的不同腳位，以及 1/8 掃描或特殊驅動面板，不能直接照此表接線。先確認面板規格及背面標示。

1備齊零件與工具先做顯示看板，門鈴可之後再加入。
  • ESP32-WROOM-32 開發板 1 塊、可傳資料的 USB 線、電腦與 Arduino IDE。
  • 標準 64×32、1/16 掃描 HUB75 RGB 面板 1 片，附 16-pin 排線與面板電源線。
  • 穩壓 5V 直流電源，額定電流依面板廠商的滿載需求選擇；例如廠商要求 5V／4A，就選至少 4A 的電源。電流不足時全白畫面可能閃爍或重啟。
  • HUB75 轉接板或可牢固接線的杜邦線、合適的電源接頭；新手優先使用帶 74AHCT245／74HCT245 等 3.3V 轉 5V 邏輯緩衝的 HUB75 轉接板，確認其腳位可配合下表。
  • 選配：與門鈴頻率及協定相容的 433MHz 接收模組。確認它的 VCC 工作電壓、DATA 輸出電壓與腳位順序；並非所有 433MHz 門鈴都能被 rc-switch 解碼。
2連接 ESP32 與面板訊號線先拔除 USB 與面板電源，找出面板的 INPUT／IN 插座。

按面板背面的訊號名稱逐一接線，不要依杜邦線顏色或開發板排針位置判斷。板上的 IO25／25 是 GPIO 25，不是第 25 根排針。排線應插入面板的 INPUT／IN，不要插到 OUTPUT／OUT。

若使用邏輯緩衝板，13 條訊號線經過緩衝器後再進入面板，GND 直接共地；依轉接板說明正確設定方向與致能。ESP32 是 3.3V 邏輯，部分面板的 5V 邏輯輸入無法穩定辨認，單純直連可能有雜點。

GPIO 5、12、15 也參與 ESP32 開機設定。外部電路不要在啟動時強制拉到錯誤電位，尤其 GPIO 12。若接上面板後無法開機，先斷電、暫時拆除面板訊號線測試，核對緩衝板及開發板規格，不要盲目換線。

3接好獨立 5V 供電與共地面板用獨立電源，ESP32 初次上傳用 USB 供電。

  1. 電源先保持關閉。把外接電源的 +5V 接面板專用電源端的 +5V／VCC，電源負極接面板電源 GND。
  2. 面板 GND、ESP32 GND 與接收模組 GND 互相連接。訊號插座也至少接一條 GND 到 ESP32。
  3. ESP32 透過 USB 供電與上傳；本接法不把面板外接 +5V 再接到 ESP32 的 5V／VIN，避免 USB 與外部電源互相回灌。
  4. 檢查正負極與端子，再開啟面板電源並插上 ESP32 USB。更動接線前先關閉兩邊電源。

面板不能由 ESP32 的 3V3 腳位或小電流開發板電源腳供電，也不要把 5V 送入 ESP32 GPIO。面板電源端子與 HUB75 訊號插座是不同接頭。

VCC依模組規格接電源；確認可在 3.3V 運作的模組才接 ESP32 3V3

如果模組需要 5V 供電，請依它的資料表供電，並確認 DATA 輸出電位；5V DATA 必須先轉換為 3.3V 邏輯再進入 ESP32。模組型號未指定，因此不能一律把 VCC 接 5V 或 3V3。GPIO 34–39 僅能輸入，沒有內部上拉／下拉；是否需要外部電阻依模組規格。

暫時沒有接收器時，關閉「啟用 433MHz 門鈴接收」，先完成看板顯示。

5準備 Arduino IDE 與 Blynk安裝開發板支援、函式庫，建立 V1 文字資料流。
  1. 安裝 Arduino IDE。在偏好設定的「額外的開發板管理員網址」加入 https://espressif.github.io/arduino-esp32/package_esp32_index.json，再於開發板管理員安裝 esp32 by Espressif Systems。
  2. 選擇符合實際板型的開發板；一般 WROOM DevKit 可選 ESP32 Dev Module。插入可傳資料的 USB 線，選擇對應序列埠；若沒有連接埠，核對 USB 線及開發板 USB 晶片驅動。
  3. 在函式庫管理員安裝 Blynk、ESP32 HUB75 LED MATRIX PANEL DMA Display、LovyanGFX、rc-switch、Adafruit GFX Library，並接受需要的相依函式庫。LovyanGFX 需包含 efontTW_16 字型。
  4. 登入 Blynk Console，建立自己的 Template，硬體選 ESP32、連線選 Wi-Fi。於 Datastreams 新增 Virtual Pin V1，資料型別選 String。
  5. 由該 Template 建立裝置，取得你的 Template ID、Template 名稱與裝置 Auth Token。在 Dashboard 加入可輸入文字的元件，綁定 V1 並儲存；手機介面也要使用相同 V1。
  6. 回到本頁「連線與硬體」，填入自己的 Blynk 資料、2.4GHz Wi-Fi 名稱及密碼，再設定想顯示的文字。頁面的預設 Template ID 只是原看板的範例，其他使用者要替換成自己的。
6下載、上傳，先點亮看板接線完成後，讓畫面與手機控制都正常運作。
  1. 按「下載完整程式碼 .ino」，開啟 LedBoard.ino；Arduino IDE 提示時建立同名的 LedBoard 資料夾。
  2. 先編譯，再上傳。若一直停在 Connecting，依開發板操作方式，在開始連線時按住 BOOT，連上後放開。
  3. 上傳後按 EN／RESET，應先看到開機畫面，再進入日期或你選定的一般訊息。日期需 Wi-Fi 與 NTP 同步，未同步時顯示「時間同步」。若剛好在休眠時間，可先啟用一般訊息做測試。
  4. 裝置在 Blynk 上線後，從 V1 傳送 測試成功/歡迎光臨。再用 test red、test green、test blue 檢查顏色，最後傳 setdate 回到日期。全白耗電較高，先確認電源容量。
  5. 若畫面全黑，先檢查面板電源、INPUT 插座、共地、亮度及夜間休眠；若顏色錯誤，核對 R／G／B 接線；若出現上下重複、錯列，先確認是否真的是 1/16 掃描面板。雜點可檢查短線、緩衝板與供電。
7讀取並加入多組門鈴 RF 碼可登錄最多 32 組；任一組符合都顯示相同提醒。
  1. 在「門鈴」啟用接收，選擇 嗅探模式，確認 DATA GPIO 與實際接線相同，下載並上傳程式。
  2. 開啟 Arduino IDE 序列埠監控視窗，速度 115200。按第一個門鈴數次，記下 [433MHz] RF code: 後方穩定重複的數字；再分別讀取其他門鈴。
  3. 把「RF 觸發模式」改為 指定模式。在「門鈴 RF 碼清單」每行填一組，或使用逗號分隔，例如：
    12345678
87654321
13572468
    這些只是示例，需改成自己的實測碼值。不要填 0；指定模式的空清單、超過 32 組或不合法碼值會被攔截。
  4. 重新下載並上傳 ESP32。測試已登錄門鈴都會觸發，未登錄的非零碼不會觸發。各碼共用同一套門鈴文字、色彩、閃爍及顯示時間。
  5. 若按鈕完全沒有碼值，檢查頻率、DATA 電位、GPIO 與天線，再確認門鈴是否為 rc-switch 支援的固定碼協定；換成指定模式不會改善無法解碼的訊號。

網頁只產生程式，不會直接修改 ESP32。每次調整 RF 碼或接收 GPIO 都需重新上傳；舊版單組碼設定檔可直接匯入，自動轉為指定模式。
