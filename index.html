安裝與使用看板管理頁

首次啟用區網管理

本版完整韌體已用 ESP32 Dev Module（4 MB）、esp32 by Espressif Systems 3.3.7 與 Minimal SPIFFS 分區編譯通過。Arduino IDE「工具 → Partition Scheme」請選 Minimal SPIFFS（1.9 MB APP with OTA）。測試使用 LovyanGFX 1.3.0、Blynk 1.4.0、ESP32 HUB75 LED MATRIX PANEL DMA Display 3.1.1、rc-switch 2.6.4、Adafruit GFX Library 2.0.0。含繁體字型與 OTA 的測試設定使用 1,742,687／1,966,080 bytes。ESP32 核心 4.0.0 搭配上述 LovyanGFX 版本編譯失敗，請選 3.3.7。

在「連線與硬體」設定至少 12 字元的管理密碼，下載韌體並以 USB 上傳一次。手機連到與看板相同的可信任 Wi-Fi，在 Arduino 序列埠監控視窗（115200）找 Board IP，使用瀏覽器開啟該 http 網址，帳號 admin，密碼為剛才設定的管理密碼。留空時區網管理和 OTA 都關閉。此管理頁使用 HTTP，僅在可信任的區網使用，請勿設定路由器轉發。

儲存與斷電恢復

在看板本機管理頁修改一般訊息、公告、亮度、排程或 RF 清單，按「儲存並套用」。設定會寫入 ESP32 的 NVS，斷電後恢復。Blynk 發送或取消的文字也會保存。暫時的門鈴警報、測試畫面與公告插播不會在重開機後重播。顯示中的一般訊息重開後重新計時。已保存的日常設定優先於新韌體的初始值，之後請在本機管理頁調整。

每個門鈴顯示不同文字

在「門鈴」選指定模式，先登錄 RF 碼，再於「各門鈴提醒」每行填 碼值|上排|下排，例如 12345678|大門來訪|請應門。另一行可填 87654321|後門送貨|請取件|#ff8000|#ffffff|30，代表上排橙色、下排白色並顯示 30 秒。只登錄碼值時沿用共用文字，最多 32 組。上板後可直接在本機門鈴清單用相同格式增刪碼值，儲存後生效。

分時亮度

在「連線與硬體」或本機管理頁啟用分時亮度，設定一般亮度、時段亮度及起迄時間。例如 18:00 至隔天 06:00 使用亮度 25，其餘時段使用 90。時段起訖相同代表全天。時間尚未同步時使用一般亮度；夜間休眠仍可讓待命畫面全黑。

公告星期、時段與到期日

在「公告」或本機管理頁啟用排程。星期填 12345 代表週一至週五，0 代表週日。指定起迄時間，例如 08:00–17:00，再填播放間隔與每次顯示分鐘數；結束時間不含在時段內。跨午夜依開始日的星期判斷，起迄相同為整天。到期日含當日，留空表示無期限。排程需 NTP 同步，且日期模式、非夜間休眠才會播放。Blynk 傳入新公告仍會立即插播，已同步且超過到期日則停止。

查看狀態與排錯

重新整理本機管理頁可查看版本、IP、Wi-Fi 訊號、Blynk 連線、NTP 同步、最近 RF 碼、目前亮度與儲存／OTA 錯誤。無法進入頁面時，先看序列埠訊息，確認手機與裝置在可互通的同一網路、IP 未改變、首次 USB 上傳時已設定管理密碼。面板或畫布初始化失敗也會在序列埠顯示。

OTA 無線更新

首次以 USB 燒錄前，在 Arduino IDE 選擇與實際 Flash 容量相符、具有兩個 OTA 應用程式分區的配置。4 MB 板可使用 Minimal SPIFFS（約 1.9 MB APP with OTA），確認編譯結果小於單一分區。網頁設定管理密碼並勾選允許 OTA，下載並上傳。下次更新時電腦與裝置在同一區網，在 Arduino IDE「工具 → 連接埠」選 ledboard- 開頭的網路埠，用相同板型與分區編譯並上傳，提示時輸入目前裝置的管理密碼。更新後會自動重啟。網路埠未出現時檢查 mDNS、防火牆與 Wi-Fi 隔離，必要時用 USB。OTA 不能更改分區表，變更分區須用 USB。

安裝後的七項實機驗收
  1. 儲存一般訊息與亮度，看到管理頁重新出現後，拔電再上電。重新登入，確認文字與亮度仍相同。
  2. 關閉嗅探模式，登錄兩個不同門鈴，分別按下並核對文字、顏色與秒數。再按未登錄的按鈕，確認看板維持原畫面。
  3. 在狀態頁確認 NTP 已同步，將亮度時段起點設在下一分鐘，使用兩個明顯不同的亮度。跨過起點與終點時，核對面板及狀態頁的亮度。
  4. 切回日期模式，在非休眠時段用當天星期及涵蓋目前時間的公告時段測試。再改成昨天到期，確認公告停止。
  5. 暫時關閉 Wi-Fi，觀察序列埠的離線提示。本機頁須在網路恢復後重新開啟，檢查 IP、NTP 與 Blynk 狀態。
  6. 用同一區網的手機登入看板，修改訊息並儲存，確認面板隨即顯示新內容。
  7. 保持供電，在 Arduino IDE 選看板網路埠並上傳含不同開機文字的韌體。確認重啟後出現新文字，原本保存的日常設定仍在。
從零開始 · 組裝教學

從一塊開發板，到你的顯示看板。

依序備料、接線、設定、上傳，再完成門鈴配對。接線表和下載的程式使用相同 GPIO。

查看腳位表
先確認型號

本教學適用 ESP32-WROOM-32／ESP32 DevKit V1（需有 GPIO 16、17），搭配單片 64×32、1/16 掃描、標準移位暫存器型 HUB75 面板。ESP32-C3／C6、WROVER／PSRAM 占用 16、17 的開發板、S3 的不同腳位，以及 1/8 掃描或特殊驅動面板，不能直接照此表接線。先確認面板規格及背面標示。

1備齊零件與工具先做顯示看板，門鈴可之後再加入。
  • ESP32-WROOM-32 開發板 1 塊、可傳資料的 USB 線、電腦與 Arduino IDE。
  • 標準 64×32、1/16 掃描 HUB75 RGB 面板 1 片，附 16-pin 排線與面板電源線。
  • 穩壓 5V 直流電源，額定電流依面板廠商的滿載需求選擇；例如廠商要求 5V／4A，就選至少 4A 的電源。電流不足時全白畫面可能閃爍或重啟。
  • HUB75 轉接板或可牢固接線的杜邦線、合適的電源接頭；新手優先使用帶 74AHCT245／74HCT245 等 3.3V 轉 5V 邏輯緩衝的 HUB75 轉接板，確認其腳位可配合下表。
  • 選配：與門鈴頻率及協定相容的 433MHz 接收模組。確認它的 VCC 工作電壓、DATA 輸出電壓與腳位順序；並非所有 433MHz 門鈴都能被 rc-switch 解碼。
2連接 ESP32 與面板訊號線先拔除 USB 與面板電源，找出面板的 INPUT／IN 插座。

按面板背面的訊號名稱逐一接線，不要依杜邦線顏色或開發板排針位置判斷。板上的 IO25／25 是 GPIO 25，不是第 25 根排針。排線應插入面板的 INPUT／IN，不要插到 OUTPUT／OUT。

  1. 電源先保持關閉。把外接電源的 +5V 接面板專用電源端的 +5V／VCC，電源負極接面板電源 GND。
  2. 面板 GND、ESP32 GND 與接收模組 GND 互相連接。訊號插座也至少接一條 GND 到 ESP32。
  3. ESP32 透過 USB 供電與上傳；本接法不把面板外接 +5V 再接到 ESP32 的 5V／VIN，避免 USB 與外部電源互相回灌。
  4. 檢查正負極與端子，再開啟面板電源並插上 ESP32 USB。更動接線前先關閉兩邊電源。

面板不能由 ESP32 的 3V3 腳位或小電流開發板電源腳供電，也不要把 5V 送入 ESP32 GPIO。面板電源端子與 HUB75 訊號插座是不同接頭。

暫時沒有接收器時，關閉「啟用 433MHz 門鈴接收」，先完成看板顯示。

5準備 Arduino IDE 與 Blynk安裝開發板支援、函式庫，建立 V1 文字資料流。
  1. 安裝 Arduino IDE。在偏好設定的「額外的開發板管理員網址」加入 https://espressif.github.io/arduino-esp32/package_esp32_index.json，再於開發板管理員安裝 esp32 by Espressif Systems。
  2. 選擇符合實際板型的開發板；一般 WROOM DevKit 可選 ESP32 Dev Module。插入可傳資料的 USB 線，選擇對應序列埠；若沒有連接埠，核對 USB 線及開發板 USB 晶片驅動。
  3. 在函式庫管理員安裝 Blynk、ESP32 HUB75 LED MATRIX PANEL DMA Display、LovyanGFX、rc-switch、Adafruit GFX Library，並接受需要的相依函式庫。LovyanGFX 需包含 efontTW_16 字型。
  4. 登入 Blynk Console，建立自己的 Template，硬體選 ESP32、連線選 Wi-Fi。於 Datastreams 新增 Virtual Pin V1，資料型別選 String。
  5. 由該 Template 建立裝置，取得你的 Template ID、Template 名稱與裝置 Auth Token。在 Dashboard 加入可輸入文字的元件，綁定 V1 並儲存；手機介面也要使用相同 V1。
  6. 回到本頁「連線與硬體」，填入自己的 Blynk 資料、2.4GHz Wi-Fi 名稱及密碼，再設定想顯示的文字。頁面的預設 Template ID 只是原看板的範例，其他使用者要替換成自己的。
6下載、上傳，先點亮看板接線完成後，讓畫面與手機控制都正常運作。
  1. 按「下載完整程式碼 .ino」，開啟 LedBoard.ino；Arduino IDE 提示時建立同名的 LedBoard 資料夾。
  2. 4 MB 的 ESP32 Dev Module 選核心 3.3.7 與 Minimal SPIFFS（1.9 MB APP with OTA）分區，再編譯上傳。若一直停在 Connecting，依開發板操作方式，在開始連線時按住 BOOT，連上後放開。
  3. 上傳後按 EN／RESET，應先看到開機畫面，再進入日期或你選定的一般訊息。日期需 Wi-Fi 與 NTP 同步，未同步時顯示「時間同步」。若剛好在休眠時間，可先啟用一般訊息做測試。
  4. 裝置在 Blynk 上線後，從 V1 傳送 測試成功/歡迎光臨。再用 test red、test green、test blue 檢查顏色，最後傳 setdate 回到日期。全白耗電較高，先確認電源容量。
  5. 若畫面全黑，先檢查面板電源、INPUT 插座、共地、亮度及夜間休眠；若顏色錯誤，核對 R／G／B 接線；若出現上下重複、錯列，先確認是否真的是 1/16 掃描面板。雜點可檢查短線、緩衝板與供電。
7讀取並加入多組門鈴 RF 碼可登錄最多 32 組；每組可顯示專屬文字。
  1. 在「門鈴」啟用接收，選擇 嗅探模式，確認 DATA GPIO 與實際接線相同，下載並上傳程式。
  2. 開啟 Arduino IDE 序列埠監控視窗，速度 115200。按第一個門鈴數次，記下 [433MHz] RF code: 後方穩定重複的數字；再分別讀取其他門鈴。
  3. 把「RF 觸發模式」改為 指定模式。在「門鈴 RF 碼清單」每行填一組，或使用逗號分隔，例如：
    12345678
87654321
13572468
    這些只是示例，需改成自己的實測碼值。不要填 0；指定模式的空清單、超過 32 組或不合法碼值會被攔截。
  4. 重新下載並上傳 ESP32。測試已登錄門鈴都會觸發，未登錄的非零碼不會觸發。每碼可指定文字、上下排顏色及顯示秒數，閃爍使用共用設定。
  5. 若按鈕完全沒有碼值，檢查頻率、DATA 電位、GPIO 與天線，再確認門鈴是否為 rc-switch 支援的固定碼協定；換成指定模式不會改善無法解碼的訊號。

網頁只產生程式，不會直接修改 ESP32。本機管理頁可直接調整 RF 碼，更改 GPIO 則需重新上傳；舊版單組碼設定檔可直接匯入，自動轉為指定模式。
